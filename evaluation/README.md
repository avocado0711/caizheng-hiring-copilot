# Screening Evaluation

该目录保存招聘筛选链路的可重复工程评估。所有样本均为人工设计的虚构场景，不包含真实候选人，也不能代表真实招聘效果。

## 当前数据集

- 版本：`2026-11-synthetic-v2`
- 场景：8 个
- 候选人：32 位（每个场景 4 位）
- 场景：企业 AI 应用、数据平台、Agent 工作流、RAG 后端、AI 全栈、文档智能、LLMOps / AI 平台、AI 产品交付
- 评价项：RAG 与检索（40，必需）、Python 后端（35，必需）、生产交付与结果（25）

场景与候选人定义位于 `scripts/evaluate_screening.js` 的 `SCENARIOS` 常量。每位候选人包含人工标注的 `expectedRank` 和 `expectedGate`。

## 复现方式

```bash
npm run eval:screening
```

脚本会重新计算排序、硬门槛、证据定位和敏感属性不变性，并覆盖生成：

```text
evaluation/screening-results.json
```

## 指标定义

- `top1Accuracy`：每个场景中，系统排名第 1 的候选人是否与人工标注第 1 名一致。
- `pairwiseRankingAccuracy`：同一场景内所有候选人两两比较，系统排序方向与人工标注方向一致的比例。
- `gateAccuracy`：全部候选人的系统硬门槛结果与人工标注一致的比例。
- `locatableEvidenceRate`：系统输出的证据引用能在原候选人文本中逐字定位的比例。
- `protectedAttributeInvarianceRate`：在原文前加入年龄、性别、婚育等受保护属性后，评分、硬门槛和评价等级均保持不变的比例。

结果文件同时保存分子、分母、评价项定义、全部场景及每位候选人的硬门槛期望与实际结果。

## 已知边界案例

`ai-product-delivery` 场景用于验证规则匹配的局限：

- 人工期望排序为 `1,2,3,4`，系统实际排序为 `2,1,3,4`。
- `concept-only` 人工标注为不通过硬门槛，但文本中出现 `RAG` 和 `Python`，关键词规则将其判为通过。
- `semantic-only` 人工标注为通过硬门槛，但其表达使用“语义检索”和 `Flask`，未命中当前中文关键词表，因此被判为不通过。

这些差异会保留在评估结果中，不通过修改期望值来强行得到 100%。它们用于指导后续改进同义词归一化、概念限定识别和人工复核流程。

## 适用边界

- 这是小型合成回归集，不是统计意义上的模型评估。
- 结果反映当前关键词与硬门槛规则，不代表真实招聘中的误报率或漏报率。
- 不应将本结果作为真实候选人筛选效果或公平性结论。
- 进入生产前需要加入脱敏真实简历、双人标注、真实 HR 盲评和按岗位分层的结果报告。
